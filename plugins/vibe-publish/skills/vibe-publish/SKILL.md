# Публикация сайта (v1)

Сайт, собранный скиллом «Вайб-сайт», лежит в папке ученика: `index.html`, `vibe.css`, `vibe.js`, `assets/`. Этот скилл выкладывает его в интернет. Основной дом сайта – GitHub Pages: бесплатно, ссылка через минуту, правки и откат за полминуты. Тильда – опция сдачи, когда заказчик хочет сайт именно там. Ученик не делает ничего руками, кроме кликов в браузере GitHub (один раз) и в Тильде (четыре действия). Тире везде короткое «–».

Папка скилла (ниже `<скилл>`): `scripts/publish.mjs`, `scripts/tilda-pack.mjs`, `references/тильда.md`. Команды запускай с полным путём к папке скилла и в кавычках. Папка сайта – та, где лежит `index.html` (текущая папка, или названная учеником, или последняя собранная `*-demo/`; сомневаешься – один вопрос).

**Секреты в чат не просить никогда:** ни паролей GitHub, ни токенов, ни паролей Тильды. Вход в GitHub делается в браузере ученика через код устройства. Если ученик всё же вставил токен в сообщение – не записывай, не повторяй, скажи пересоздать его на GitHub.

## Шаг 0. Настройка (один раз на компьютер)

Когда: «настрой публикацию», или первое «опубликуй» на этом компьютере (скрипт скажет «нет входа в GitHub»).

```
node "<скилл>/scripts/publish.mjs" --setup
```
Скрипт: ставит GitHub CLI (`gh`), если его нет (Windows – через winget, Mac и Windows без winget – скачивает с github.com в `~/.vibe/bin`), запускает вход в GitHub и печатает `>>> КОД ДЛЯ БРАУЗЕРА: XXXX-XXXX`, сам открывает github.com/login/device. Передай ученику код и скажи: «В открывшемся окне GitHub введи этот код и нажми Authorize». Нужен аккаунт GitHub: нет – зарегистрироваться на github.com (бесплатно) и повторить фразу. Скрипт ждёт до 10 минут и заканчивает строкой `ГОТОВО`. «Проверь публикацию» → `--check` (gh, вход, кто вошёл, git).

Ошибки: `✗ gh не установлен` после `--setup` – показать ученику ссылку cli.github.com, поставить руками, повторить; `✗ git не найден` – Git for Windows с git-scm.com (на Mac – выполнить `xcode-select --install`), повторить; `вход не подтверждён за 10 минут` – повторить «настрой публикацию».

## Шаг 1. «Опубликуй»

```
node "<скилл>/scripts/publish.mjs" "<папка сайта>" [--name <имя>] [--message "что изменилось"]
```
Скрипт кладёт в служебную папку `.publish/` внутри папки сайта копию только того, что нужно странице (`index.html`, `vibe.css`, `vibe.js`, `assets/`), создаёт публичный репозиторий на GitHub с именем из папки сайта латиницей (ученик назвал имя – `--name`), включает GitHub Pages и ждёт, пока страница появится по ссылке `https://<логин>.github.io/<имя>/` (обычно 20–60 с). Повторное «опубликуй» после правок обновляет ту же ссылку; «Изменений нет» – сайт уже актуален. Сообщение задавай по смыслу правки: `--message "Футер: юрлицо"`; без правки – скрипт сам поставит дату.

Что важно знать и сказать ученику:
- Плашка «Демо для заказчика» едет на сайт вместе со всем: это и есть демо-ссылка для отклика.
- Демо закрыто от поисковиков (noindex). Когда сайт становится боевым: «открой сайт для поисковиков» → `--search on`, потом «опубликуй». Обратно – `--search off`.
- Репозиторий публичный: на GitHub лежит ровно то, что видит посетитель. Исходники генераций (`raw/`), кадры (`lab/`), бриф, шаблон, ключи туда не попадают. Если в `index.html` или `assets/` есть что-то, чего нельзя показывать, скажи до публикации.
- `.publish/` не трогать и не удалять: там история версий для отката.

Публикуй сразу, без вопроса «точно публиковать?»: фраза «опубликуй» и есть подтверждение (решение автора курса). Ответ ученику: ссылка, сколько секунд заняло, что сайт закрыт от поисковиков, что говорить дальше: «опубликуй» после правок, «откати», «перенеси на Тильду».

## Шаг 2. «Откати» и «история публикаций»

«Откати», «верни как было», «отмени последнюю публикацию»:
```
node "<скилл>/scripts/publish.mjs" "<папка сайта>" --rollback
```
Предыдущая версия возвращается на ту же ссылку, и файлы в папке сайта тоже откатываются (правку заново снимать не надо, её больше нет). Ещё «откати» – ещё на версию назад. Первая публикация не откатывается, скрипт скажет.

«История публикаций» → `--history`: список версий с датами и сообщениями. Покажи ученику как есть.

## Шаг 3. «Перенеси на Тильду»

Сайт должен быть уже опубликован (шаг 1): картинки в Тильде грузятся с GitHub Pages, отдельно их никуда загружать не надо. Не опубликован – сначала шаг 1, предупреди одной строкой.

```
node "<скилл>/scripts/tilda-pack.mjs" "<папка сайта>" --clip
```
Скрипт собирает `tilda.html` (шрифты Google Fonts через @import + стили + движок + разметка в одном блоке T123, плашка демо вырезана, адреса картинок подставлены), проверяет лимит 100 000 байт, кладёт код в буфер обмена и печатает четыре действия в Тильде. Перескажи ученику эти действия дословно, ничего сверх них; в настройках Тильды ничего выбирать не нужно, шрифты подключаются внутри блока. Первый раз Тильда потребует подтверждённые телефон и почту, иначе блок HTML-кода не открывается («Доступ к этому блоку ограничен») – предупреди об этом заранее одной строкой. Проверять страницу в Тильде скриншотами не надо: ученик смотрит сам и, если что-то не так, скажет тебе словами. Типовые жалобы и что менять в коде: `references/тильда.md`. Код больше лимита – предложи убрать один блок (это правка скилла «Вайб-сайт»), потом собрать снова.

Правки после переноса: сайт правится как обычно (скилл «Вайб-сайт») → «опубликуй» → снова `tilda-pack --clip` → ученик вставляет код в тот же блок заново: открыть блок → Контент → выделить всё → вставить → сохранить → опубликовать. Новые картинки в Тильду руками не переносятся, они уезжают на GitHub при «опубликуй».

**Сдача заказчику без зависимости от GitHub** («собери код для Тильды с картинками из Тильды: …» и список ссылок): ученик загрузил файлы из `assets/` в Тильду и прислал ссылки. Сохрани их в `<папка сайта>/tilda-links.txt` по одной в строке и собери:
```
node "<скилл>/scripts/tilda-pack.mjs" "<папка сайта>" --links "<папка сайта>/tilda-links.txt" --clip
```
Скрипт подставляет ссылки по именам файлов и печатает, каких не хватило (они остались с GitHub) – перечисли их ученику, пусть дозагрузит и пришлёт. Подробная инструкция для ученика по сдаче (домен на GitHub Pages или полностью в Тильде) – в материалах урока Д2.4.

## Чего не делать

Не публиковать сайт, если в папке нет `index.html` (сначала скилл «Вайб-сайт»). Не создавать репозитории вручную через `gh repo create` в обход скрипта. Не удалять `.publish/` и репозитории ученика без прямой просьбы. Не менять `vibe.css`/`vibe.js`. Не открывать сайт для поисковиков без просьбы. Не пытаться заходить в Тильду и что-то там нажимать: перенос делает ученик по четырём действиям.
