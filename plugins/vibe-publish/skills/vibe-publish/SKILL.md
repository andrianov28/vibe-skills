# Публикация сайта (v1.1)

Сайт, собранный скиллом «Вайб-сайт», лежит в папке ученика: `index.html`, `assets/` и стили со скриптами (у каркасов – движок `vibe.css` + `vibe.js`, у сайтов «по номеру» из Галереи 45 – `style-*.css` + `style.js`). Этот скилл выкладывает его в интернет. Основной дом сайта – GitHub Pages: бесплатно, ссылка через минуту, правки и откат за полминуты. Тильда – опция сдачи, когда заказчик хочет сайт именно там. Ученик не делает ничего руками, кроме кликов в браузере GitHub (один раз); перенос в Тильду Клод делает сам через «Claude в Chrome». Тире везде короткое «–».

Папка скилла (ниже `<скилл>`): `scripts/publish.mjs`, `scripts/tilda-pack.mjs`, `references/тильда.md`. Команды запускай с полным путём к папке скилла и в кавычках. Папка сайта – та, где лежит `index.html` (текущая папка, или названная учеником, или последняя собранная `*-demo/`; сомневаешься – один вопрос).

**Секреты в чат не просить никогда:** ни паролей GitHub, ни токенов, ни паролей Тильды. Вход в GitHub делается в браузере ученика через код устройства. Если ученик всё же вставил токен в сообщение – не записывай, не повторяй, скажи пересоздать его на GitHub.

## Шаг 0. Настройка (один раз на компьютер)

Когда: «настрой публикацию», или первое «опубликуй» на этом компьютере (скрипт скажет «нет входа в GitHub»).

```
node "<скилл>/scripts/publish.mjs" --setup
```
Скрипт: ставит GitHub CLI (`gh`), если его нет (Windows – через winget, Mac и Windows без winget – скачивает с github.com в `~/.vibe/bin`), запускает вход в GitHub и печатает `>>> КОД ДЛЯ БРАУЗЕРА: XXXX-XXXX`, сам открывает github.com/login/device. Передай ученику код и скажи: «В открывшемся окне GitHub введи этот код и нажми Authorize». Нужен аккаунт GitHub: нет – зарегистрироваться на github.com (бесплатно) и повторить фразу. Скрипт ждёт до 10 минут и заканчивает строкой `ГОТОВО`. «Проверь публикацию» → `--check` (gh, вход, кто вошёл, git).

Ошибки: `✗ gh не установлен` после `--setup` – показать ученику ссылку cli.github.com, поставить руками, повторить; `✗ git не найден` – Git for Windows с git-scm.com (на Mac – выполнить `xcode-select --install`), повторить; `вход не подтверждён за 10 минут` – повторить «настрой публикацию».

## Шаг 1. «Опубликуй»

```
node "<скилл>/scripts/publish.mjs" "<папка сайта>" [--name <имя>] [--message "что изменилось"]
```
Скрипт кладёт в служебную папку `.publish/` внутри папки сайта копию только того, что нужно странице (`index.html`, все подключённые ею стили и скрипты, `assets/`), создаёт публичный репозиторий на GitHub с именем из папки сайта латиницей (ученик назвал имя – `--name`), включает GitHub Pages и ждёт, пока страница появится по ссылке `https://<логин>.github.io/<имя>/` (обычно 20–60 с). Повторное «опубликуй» после правок обновляет ту же ссылку; «Изменений нет» – сайт уже актуален. Сообщение задавай по смыслу правки: `--message "Футер: юрлицо"`; без правки – скрипт сам поставит дату.

Что важно знать и сказать ученику:
- Плашка «Демо для заказчика» едет на сайт вместе со всем: это и есть демо-ссылка для отклика.
- Демо закрыто от поисковиков (noindex). Когда сайт становится боевым: «открой сайт для поисковиков» → `--search on`, потом «опубликуй». Обратно – `--search off`.
- Репозиторий публичный: на GitHub лежит ровно то, что видит посетитель. Исходники генераций (`raw/`), кадры (`lab/`), бриф, шаблон, ключи туда не попадают. Если в `index.html` или `assets/` есть что-то, чего нельзя показывать, скажи до публикации.
- `.publish/` не трогать и не удалять: там история версий для отката.

Публикуй сразу, без вопроса «точно публиковать?»: фраза «опубликуй» и есть подтверждение (решение автора курса). Ответ ученику: ссылка, сколько секунд заняло, что сайт закрыт от поисковиков, что говорить дальше: «опубликуй» после правок, «откати», «перенеси на Тильду».

## Шаг 2. «Откати» и «история публикаций»

«Откати», «верни как было», «отмени последнюю публикацию»:
```
node "<скилл>/scripts/publish.mjs" "<папка сайта>" --rollback
```
Предыдущая версия возвращается на ту же ссылку, и файлы в папке сайта тоже откатываются (правку заново снимать не надо, её больше нет). Ещё «откати» – ещё на версию назад. Первая публикация не откатывается, скрипт скажет.

«История публикаций» → `--history`: список версий с датами и сообщениями. Покажи ученику как есть.

## Шаг 3. «Перенеси на Тильду» – Клод делает всё сам

Фразы: «перенеси на Тильду», «перенеси сайт из папки … на Тильду», «заказчик купил, переносим в Тильду», «обнови сайт в Тильде». **Основной путь – автоматический:** Клод сам работает в Тильде ученика через расширение «Claude в Chrome» – создаёт страницу, загружает картинки, собирает и вставляет код, публикует, проверяет и отдаёт ссылку. Ученик только говорит фразу. Порядок действий в браузере, проверенный в живой Тильде 02.10.2026, – `references/тильда-авто.md`: прочитай его целиком перед первым кликом и иди строго по нему.

Перед стартом одной строкой скажи ученику, что сейчас будет («Открываю вашу Тильду в Chrome, создаю страницу и переношу сайт – 3–5 минут, ничего нажимать не нужно»). Остановиться и попросить ученика можно только в трёх случаях: расширение не подключено, в Chrome не выполнен вход в Тильду, Тильда просит подтвердить телефон. Пароль и номер телефона ученик вводит сам, Клод их не вводит никогда.

Результат: страница «Компания – Город – ниша» в Тильде ученика, картинки и шрифты не зависят от GitHub, галерея с картинками скрыта на той же странице. Ученику – ссылка вида `имя.tilda.ws/адрес` и одна строка: **«галерею со страницы не удаляйте – в ней живут картинки сайта»**.

**Правки после переноса** («обнови сайт в Тильде»): сайт правится как обычно (скилл «Вайб-сайт»), потом тот же автоматический путь – он находит существующую страницу по адресу, догружает новые картинки и заменяет код в том же блоке. Блок кода не превращается в обычные блоки Тильды: тексты правим словами через Клода, не в редакторе Тильды.

**Передача страницы заказчику** – только руками ученика, Клод подсказывает путь и не нажимает «Передать» (необратимо, чужая почта). У заказчика свой аккаунт Тильды с ОПЛАЧЕННЫМ тарифом Personal или Business (пробный период и промокод не считаются, платит заказчик). Ученик: страница → «Настройки» → «Действия» → «Передать страницу» → почта аккаунта заказчика → «Передать». Заказчик у себя в «Моих сайтах» жмёт «Принять» – только тогда страница уезжает и пропадает у ученика (сама, удалять руками нельзя). Галерея с картинками на той же странице, поэтому картинки уезжают вместе с ней.

### Запасной путь – руками (расширения нет или оно не отвечает)

Скажи одной строкой, что автоматически не получится и почему, и предложи: поставить расширение (инструкция в материалах урока) или перенести руками. Руками:
1. **Картинки в Тильду.** Открой ученику папку картинок (`start "" "<папка сайта>assets"` на Windows, `open` на Mac) и дай действия: в Тильде «Создать новую страницу» → «Пустая страница» → «Галерея» в нижней панели блоков → навести на галерею → «Контент» → «Загрузить файлы» → выделить ВСЕ картинки из открытой папки (папку fonts не трогать) → удалить четыре фото-заглушки Тильды (корзина в строке) → «Сохранить и закрыть» → «Опубликовать». Прислать адрес страницы.
2. **Собрать код:** `node "<скилл>/scripts/tilda-pack.mjs" "<папка сайта>" --tilda "<адрес страницы>" --clip`. Скрипт сам читает опубликованную страницу, берёт ссылки на картинки по именам файлов, скрывает галерею, свои шрифты каркаса переводит на Google Fonts и проверяет, что ссылок на GitHub в коде нет. Пишет «НЕ ЗАГРУЖЕНЫ» – перечисли файлы ученику: догрузить в ту же галерею, опубликовать, «собери ещё раз».
3. **Блок кода:** «Все блоки» → «Другое» → T123 → навести → «Контент» → вставить (Ctrl+V) → «Сохранить и закрыть» → «Опубликовать». Первый раз Тильда попросит подтвердить телефон – это ученик делает сам.

Быстрый вариант для демо без передачи заказчику (картинки остаются на GitHub, сайт должен быть опубликован шагом 1): `tilda-pack.mjs "<папка сайта>" --clip` и только пункт 3. Типовые жалобы на страницу в Тильде и что менять в коде – `references/тильда.md`. Код больше лимита 100 000 байт – предложи убрать один блок (правка скилла «Вайб-сайт») и собрать снова. Старый ключ `--links <файл>` оставлен для совместимости, шрифты он не переводит.

## Чего не делать

Не публиковать сайт, если в папке нет `index.html` (сначала скилл «Вайб-сайт»). Не создавать репозитории вручную через `gh repo create` в обход скрипта. Не удалять `.publish/` и репозитории ученика без прямой просьбы. Не менять `vibe.css`/`vibe.js`. Не открывать сайт для поисковиков без просьбы. В Тильде не делать ничего сверх переноса: не удалять и не передавать страницы, не менять настройки сайта и тариф, не вводить пароли и телефон. Работать только в своей вкладке «Claude в Chrome».

## Обновление скиллов курса («обнови скиллы»)

Ученик говорит «обнови скиллы», «обнови скиллы курса», «поставь свежие версии скиллов» – выполни:

```
node ~/.claude/plugins/marketplaces/vibe-skills/update.mjs
```
(на Windows: `node "%USERPROFILE%\.claude\plugins\marketplaces\vibe-skills\update.mjs"`). Скрипт делает `git pull` в папке каталога и копирует свежие файлы каждого установленного скилла поверх всех папок версий в `~/.claude/plugins/cache/vibe-skills/` – приложение загружает именно их и само новую версию не подхватывает. Если файла `update.mjs` ещё нет (старый клон каталога): сначала `git -C ~/.claude/plugins/marketplaces/vibe-skills pull`, потом команду повторить. Если нет самой папки каталога – каталог не подключён, подключить как в уроке про первый скилл (`extraKnownMarketplaces` в `~/.claude/settings.json`). Ничего не удаляй, `settings.json` и ключи не трогай. В ответ – список скиллов с версиями из вывода скрипта и фраза «новые версии подхватятся в новом чате». Скиллы, которых нет в кэше, скрипт не ставит – их включают отдельной фразой.
